# 事業02: AIニュースレター「AI Ops Weekly」

担当エージェント: `.claude/agents/newsletter-agent.md`

## 概要
AI・生産性ツール関連の実務者向けに、週刊(想定)で配信するニュースレター。パブリケーション名は「AI Ops Weekly」。

## 配信基盤: Buttondown(2026-09-28にSubstackから乗り換え)
配信基盤としてButtondown(https://buttondown.com/)を採用する。Substackには公式の配信APIがなく毎号ユーザーが手動でコピペ・送信する必要があり「半自動ビジネス」として弱いという課題があったため、公式の配信API(`https://api.buttondown.com/v1/`)を持つButtondownに移行した。APIキーが登録された状態であれば、下書き作成から実際の配信までエージェントが自律的に行える。

- 認証: `Authorization: Token $BUTTONDOWN_API_KEY` ヘッダー([Buttondown API Authentication](https://docs.buttondown.com/api-authentication))
- メール作成: `/emails` エンドポイント。2026年4月以降のAPIバージョンではデフォルトのステータスが`draft`になり、誤って即送信されない安全設計になっている([Emails API](https://docs.buttondown.com/api-emails-list))
- 配信(送信)には `status` を `about_to_send` に変更する操作が必要(確認ステップあり)

APIキーは**リポジトリにコミットしない**。`.env`(gitignore対象)またはこの実行環境のSecrets設定で管理する。参考として`.env.example`に変数名のみ記載する。

note.comについては、公開APIが存在せず自動化できないため、今回は着手しない。将来的にButtondownでの配信基盤が軌道に乗った段階で、手動運用の補助チャネルとして併用を検討する(下記「今後の展望」参照)。

## 収益モデル
- 開始時は無料配信で購読者を増やす
- Buttondown APIを使い、下書き作成→(APIキー登録後)配信までをエージェントが自律的に行える体制を構築する
- 一定規模に達したら有料プラン(Stripe連携)を検討

## 今後の展望(将来フェーズ)
- note.comの併用: Buttondownでの自動配信基盤が安定してから検討。note.comは公開APIがないため、併用する場合は転記作業が別途必要になる想定。

## 進行フェーズ(親セッション方針)
各事業共通で「1. 基盤の構築 → 2. プランの提示 → 3. 世に出す(公開)」の3ステップで進行。現在はフェーズ1(基盤構築)。

**基盤構築の定義(訂正版・2026-09-25):** 号のドラフト作成そのものは基盤構築ではなく後続フェーズの作業。基盤構築とは、事業運営に必要なプラットフォームへの登録・決済手段の確立を指す。具体的には下記セットアップチェックリストの「配信基盤(Buttondown)のアカウント開設・APIキー取得」がこれにあたる。アカウント開設・APIキー発行はユーザー本人の操作が必要なため、Claude Codeセッションは代行できず、スクリーンショット越しにユーザーをガイドする形で進める。基盤が整うまでは「プランの提示」フェーズに進まない。

実配信の開始・購読者募集の告知などユーザー以外の目に触れる「公開」作業(フェーズ3)に進む前には、必ず具体的な公開プラン(何を・いつ・どのように)をチャットでユーザーに提示し、承認を得てから着手する。

## 公開プラン(2026-09-28 ユーザー承認済み・Buttondown移行により手順を更新予定)
1. 配信頻度: 週刊
2. 初回配信号: 内部ドラフト`issue-004.md`の内容を、実際の配信では「第1号」として使用(第1〜3号は開発初期のテンプレート検証用で内容が古くなったため実配信しない)
3. 配信タイミング: まずテスト配信(自分宛て、または下書き確認)→ 問題なければ本配信。具体的な配信日はユーザーが決定
4. 購読者集め: 初回はSNS・知人への共有からスタート

Substack上ではすでに同内容の記事を作成済みだが、配信基盤をButtondownに切り替えるため、Substackでの配信は行わない(下書きはSubstack側にも残るが未送信のまま)。
