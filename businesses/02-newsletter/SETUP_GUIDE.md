# 配信基盤セットアップガイド(人間向け・Buttondown版)

このガイドは、ニュースレター「AI Ops Weekly」の配信を開始するために必要な、人間側の操作手順をまとめたものです。Claude Codeセッションはアカウント開設や決済設定を代行できないため、ここに記載の手順はユーザー自身に実施していただき、必要に応じてスクリーンショットを共有いただければ、次の手順や設定内容の確認をこのセッションでサポートします。

> 2026-09-28更新: 配信基盤をSubstackからButtondownに変更しました。Substackには公式の配信APIがなく毎号手動でコピペ・送信する必要がありましたが、Buttondownは公式API(`https://api.buttondown.com/v1/`)を持ち、APIキーを登録すればエージェントが下書き作成から配信まで自律的に行えます。

## なぜButtondownか

- 公式の配信API(下書き作成・購読者管理・実配信)を持つ
- APIキーによる認証(`Authorization: Token $BUTTONDOWN_API_KEY`)で、Claude Codeセッションからも(APIキーが環境のSecretsに登録されていれば)操作可能
- Markdown形式の本文をそのままAPIに渡せるため、このリポジトリの`issues/issue-XXX.md`との相性が良い
- 参考: [Buttondown API認証ドキュメント](https://docs.buttondown.com/api-authentication)、[Emails APIドキュメント](https://docs.buttondown.com/api-emails-list)

## セットアップ手順

1. **アカウント開設**
   - https://buttondown.com/ にアクセスし、アカウントを作成
   - 配信用メールアドレスを設定
2. **ニュースレターの基本設定**
   - ニュースレター名「AI Ops Weekly」・説明文・ロゴ(任意)を設定
   - 配信頻度(週刊)を選択
3. **APIキーの発行**
   - Buttondownダッシュボードの **Settings → API → Keys** に進む
   - 新しいAPIキーを発行(名前は「Claude Code連携」など分かりやすいものを推奨)
   - 発行されたキーは一度しか表示されない場合があるため、必ずその場でコピーしておく
4. **APIキーをこの実行環境に登録**
   - **チャットにキーを直接貼らないでください**(パスワードと同様、会話記録に残ってしまいます)
   - この実行環境のSecrets設定で `BUTTONDOWN_API_KEY` という名前で登録してください(具体的な登録方法が分からない場合は、その旨を伝えていただければ環境のドキュメントを確認して案内します)
   - リポジトリの `.env.example` に変数名のみ記載してあります(実際の値はコミットしません)
5. **ドラフトの投入・配信**
   - APIキーが登録されたら、このセッションが`issues/issue-XXX.md`の内容をButtondown APIで下書きとして作成できます
   - 下書きの内容はButtondownの管理画面でも確認可能。問題なければユーザーの最終判断で配信(送信)を実行します(APIでの実送信も、確認ステップを踏んだ上で対応可能)
6. **購読者募集の準備**
   - 購読フォームのリンクを取得(SNS・他事業サイトからの導線に利用予定)

## 進捗を共有する場合

操作中の画面をスクリーンショットで共有いただければ、次に何を設定すべきか、どの項目を埋めればよいか等をこのセッションで確認・案内します。**ただしAPIキーやパスワードなどの認証情報はスクリーンショットにも極力写さないようご注意ください。**

## Substackについて

これまでSubstack(`soramathis.substack.com`)でアカウント開設・パブリケーション設定・第1号の下書き作成まで進めていましたが、配信基盤をButtondownに変更したため、Substackでの実配信は行いません。Substackアカウント自体は残していますが、当面利用予定はありません。

## 将来のStripe連携(有料プラン)について

購読者が一定規模に達し、有料プランを検討する段階になったら、Buttondown側のStripe連携設定が必要です。親セッションでのStripe連携作業(`businesses/03-saas-tool/` 等)が良い前例になるため、その際は同様の進め方(スクリーンショットでの案内)を予定しています。現時点では未着手です。

## note.comについて(将来フェーズ)

note.comは公開APIがなく自動化できないため、現時点では着手しません。Buttondownでの自動配信基盤が安定してから、手動運用の補助チャネルとしての併用を検討します。
