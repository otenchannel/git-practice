## 3. つまずきの実録

ここからが、この記事の本題です。設定でつまずいた箇所を、「症状 → 原因 → 直し方 → 学び」の順に書きます。
なお、AI アシスタントと一緒に進めました。AI は私の画面を直接は見られないので、**ログの1行や画面の内容を、私が文字や画像で伝える**形でした。

### 3-1. 購入ボタンを押すとエラーになる(401)

**症状**
販売ページで購入ボタンを押すと、「エラーが発生しました」と出て、Stripe の決済画面に進めませんでした。
サーバーのログには、こう出ていました。

```
stripe checkout failed for order xxxx: HTTP Error 401: Unauthorized
```

**原因**
`STRIPE_SECRET_KEY` に、キーの先頭の `sk_test_` しか入っていませんでした。Stripe の画面では、シークレットキーは最初、伏せ字で表示されます。その状態でコピーしたため、見えている部分しかコピーできていませんでした。
Stripe が返したエラー本文にも、はっきり出ていました。

```
"message": "Invalid API Key provided: sk_test_"
```

**直し方**
Stripe のダッシュボードで、キーの「表示」を押して、伏せ字を解除してから、全体をコピーし直しました。

**学び**
同じエラーが、2回続きました。「更新したのに直らない」とき、**値が本当に入っているかを疑う**のが近道です。
ただし、キーの中身をログに出すわけにはいきません。そこで、**キーの長さと、先頭の8文字だけ**を起動ログに出すようにしました。

```python
print(f"stripe key: length={len(STRIPE_SECRET_KEY)} prefix={STRIPE_SECRET_KEY[:8]!r}")
```

最初は `length=8`(途中切れ)でした。直したあとは `length=107` になりました。キー本体を見せずに、入力ミスを切り分けられます。

### 3-2. Webhook の署名シークレットが、仮の値のままだった

**症状**
3-1 のログを見たとき、同じ行に、Webhook の署名シークレットの長さも出ていました。

```
stripe key: length=8 prefix='sk_test_' webhook_secret_length=11
```

**原因**
私は、署名シークレットを「更新した」つもりでした。ところが、長さは `11` でした。これは、最初に仮で入れた `whsec_dummy` と、同じ長さです。本物のシークレットは、もっと長い値です。
つまり、「更新した」つもりが、**実際には本物の値が入っていませんでした**。

**直し方**
Stripe の Webhook の詳細画面で、署名シークレットを「表示」してから、全体をコピーして、入れ直しました。長さが `38` になりました。

**学び**
3-1 と同じ落とし穴です。**秘密の値は、中身を見ずに、長さだけで確認できる**ようにしておくと、設定ミスの発見が早くなります。

### 3-3. 決済ページが作れない(400、税コード)

**症状**
キーを直すと、エラーの内容が変わりました。サーバーのログには、こう出ていました(長い文なので、要点だけ)。

```
Stripe 400: Invalid line_items[0]: the product tax code is missing.
... Product tax code is required for Managed Payments, which is enabled by default on your account.
If you want to disable Managed Payments on this session, you can pass managed_payments[enabled]=false.
```

**原因**
Stripe のアカウントで、**Managed Payments が既定で有効**になっていました。この機能では、商品の税コードが必須です。私のコードは、税コードを送っていなかったので、拒否されました。
【確認】Managed Payments の正確な仕組み(Stripe が販売者として税金などを扱う機能、という理解で合っているか)は、Stripe の公式ドキュメントで確認して、書き直す。

**直し方**
エラー文が案内していたとおり、この決済では `managed_payments[enabled]=false` を送って、無効にしました。

```python
"managed_payments[enabled]": "false",
```

私は「自分が販売者として売る」前提で、販売ページと、特定商取引法の表記を作っています。その前提と合うので、この方法を選びました。使う場合は、税金の扱いが変わるので、税理士や税務署に確認してください。

**学び**
エラーが出たときに、**Stripe の返事の本文(エラーの理由)を、ログに残す**ようにしました。最初は `HTTP Error 400` としか出ず、理由が分かりませんでした。本文には、原因と、直し方まで書いてありました。

```python
except urllib.error.HTTPError as e:
    raise RuntimeError(f"Stripe {e.code}: {e.read()[:500].decode('utf-8', 'replace')}")
```

### 3-4. 決済は通ったのに、メールが届かない

**症状**
Stripe の決済画面で、テストカードを使って支払いました。「ご購入ありがとうございます」の画面に戻りました。ですが、**ダウンロードURLのメールが、届きませんでした**。
Stripe のダッシュボードで、Webhook の配信結果を見ると、HTTP ステータスが `400` でした。

**原因**
私のサーバーは、メールの送信に失敗すると、**わざと 400 を返す**作りにしていました。Stripe が、失敗した通知を、あとで自動的に再送してくれるからです。メール送信を直せば、あとから届きます。
つまり、400 は、「Webhook が壊れている」のではなく、**「メールの送信で失敗した」というサイン**でした。

**直し方**
サーバーのログを見て、原因を探しました(次の 3-5 と 3-6)。

**学び**
最初は、400 になる理由が、ログに残っていませんでした。理由は、署名の検証失敗、注文が見つからない、金額の不一致、メール送信の失敗の、4通りありました。**失敗の理由ごとに、ログを1行出す**ようにしました。

```
mail failed for order xxxx via smtp.example.com:587 user_set=True from='...': SMTPServerDisconnected: ...
```

ホスト名、ポート、例外の種類は出しますが、**パスワードは出しません**。

### 3-5. ログが見えない

**症状**
サーバーを動かしている Render の画面で、ログを開いても、「Awaiting logs...」と出るだけで、何も表示されませんでした。

**原因**
画面の右上が、「**Live tail**」になっていました。これは、**画面を開いたあとに出たログだけ**を流す表示です。先に実行したフローのログは、出ません。

**直し方**
「Live tail」を、時間の範囲(「Last 7 days」など)に切り替えました。検索欄に `mail failed` と入れると、目的の行が見つかりました。

**学び**
「何も出ない」ときは、**サービスの不具合を疑う前に、画面の表示設定を疑います**。

### 3-6. `Name or service not known`

**症状**
ログに、こう出ていました。

```
mail failed for order xxxx via you@example.com:587 ...: gaierror: [Errno -2] Name or service not known
```

**原因**
`SMTP_HOST` に、**メールアドレスを入れていました**。`SMTP_HOST` には、メールサーバーの**ホスト名**(例: `smtp.gmail.com`)を入れます。メールアドレスは、サーバーの名前として解決できないので、このエラーになります。
ログの `via ◯◯:587` の部分に、`SMTP_HOST` に入っていた値が、そのまま出ていたので、すぐ気づけました。

**直し方**
`SMTP_HOST` を `smtp.gmail.com` に直しました。メールアドレスは、`SMTP_USER` に入れます。

**学び**
環境変数の名前は、似ていて、紛らわしいものです。手順書には、**各項目に、具体的な値の例**を書いておきます。ログに、ホスト名とポートを出しておくと、入力ミスに気づきやすくなります。
