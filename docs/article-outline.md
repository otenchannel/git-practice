# 無料記事の骨子(最初の1本)

目的: 「買ってもらう」ためではなく、**このテーマに関心のある人が実際にいるかを確かめる**ための記事。商品はまだ完成していないので、末尾は「準備中・反応がほしい」にする。
出し先は未定(Zenn / note / 自分のブログなど)。Markdown で書けば、どこにも流用できる。

## タイトル案(どれか1つ)
1. AI と一緒に、デジタル商品の販売システムを作って、つまずいたこと全部
2. Stripe + メール納品を自前で作ったら、設定ミスだらけだった話(直し方つき)
3. 自前の販売サイトを1日で動かすまでに、7回つまずいた

> 「全部」「7回」のような数字を入れる場合は、**本文の数と必ず合わせる**。

## 想定読者
プログラミングに少し触れたことがあり、デジタル商品を自分で売る仕組みに関心がある人。

## 構成と、各節に書くこと

### 1. 導入(300〜400字)
- 何を作ったか: 「決済 → メール → ダウンロード」が自動で動く販売サイト
- なぜ作ったか(**あなた自身の動機を一文、正直に**)
- 使ったもの: Python、Stripe(サンドボックス)、Render、Gmail の SMTP、AI アシスタント
- この記事で分かること: 全体の流れと、**実際にハマった点と、その直し方**

### 2. 全体像(図があると良い)
```
購入ボタン → Stripe の決済画面 → 支払い完了
   → Stripe が Webhook を送る → 署名を検証 → 期限付きURLを作る → メールで送る
```
- 自動化できる範囲(納品)と、できない範囲(商品づくり、集客)を一文で

### 3. つまずきの実録(**この記事の中心。ここを一番厚く**)
各項目は「症状 → 原因 → 直し方 → 学び」の4点で書く。

| # | 症状 | 原因 | 直し方 | 学び |
|---|---|---|---|---|
| 1 | 購入ボタンを押すと、エラー(401) | `STRIPE_SECRET_KEY` に `sk_test_` しか入っていなかった。画面で伏せ字のままコピーした | キーを「表示」してから全体をコピー | **キーの長さだけをログに出す**と、本体を見せずに切り分けられる |
| 2 | 同じエラーが続く | Webhook の署名シークレットも仮の値のままだった | 本物の値に差し替え | 起動ログで長さを確認する |
| 3 | 決済ページが作れない(400) | Stripe の Managed Payments が既定で有効で、商品の税コードを要求された | この決済では無効にする(自分が販売者の前提) | **エラー本文をログに出す**と、原因が文面に書いてある |
| 4 | 決済は通ったのに、メールが来ない | Webhook が 400 を返していた(メール送信の失敗) | ログで原因を探す | 失敗の理由をログに出さないと、どこで止まったか分からない |
| 5 | ログが見えない | 「Live tail」は、画面を開いた後のログだけを表示する | 時間範囲を「Last 7 days」などに変える | 画面の設定で「何も出ない」ことがある |
| 6 | `Name or service not known` | `SMTP_HOST` にメールアドレスを入れていた | ホスト名(`smtp.gmail.com`)に直す | 設定項目の意味を、例つきで書いておく |
| 7 | Gmail のアプリパスワードが作れない | 2段階認証が有効になっていなかった | 先に2段階認証を有効にする | 前提条件を手順の先頭に書く |

- 失敗した Webhook は、Stripe の「再送信」でやり直せる(購入し直さなくてよい)
- **AI アシスタントとの進め方**: ログの1行を貼って原因を絞る、という形が効いた。ただし、AI は画面を直接見られないので、**画面の内容を人が伝える**必要があった(正直に書く)

### 4. 作り込んだ安全面(短く)
- モック決済を、本番では無効にする(誰でも「支払い済み」を偽造できてしまうため)
- 危険な設定(既定の秘密鍵、http の URL など)では起動を拒否する
- 同じ通知が二重に来ても、メールは1通だけ送る
- 秘密情報は、コードではなく環境変数に置く

### 5. まだ終わっていないこと(正直に)
- 本番(Stripe の実運用)には、まだ切り替えていない
- 特商法の表記、商品の中身、集客は、これから
- 「これで稼げる」とは言えない。仕組みは、売る場を用意しただけ

### 6. おわりに(CTA。**売り込みにしない**)
- 手順書とスターターキットの形でまとめることを検討している
- 「読みたい」「ここが知りたい」という反応を、コメントや X で教えてほしい
- 反応が、作るかどうかの判断材料になる

## 導入の下書き(そのまま使える形。自分の言葉に直す)
> デジタル商品を自分で売りたいと思い、決済からメール納品まで自動で動く販売サイトを作りました。
> Stripe で決済し、完了すると、期限付きのダウンロードURLが、購入者にメールで届く仕組みです。
> 使ったのは、Python、Stripe(テスト環境)、Render、Gmail の SMTP、そして AI アシスタントです。
> 結論から言うと、**動くまでに、設定のつまずきが、何度もありました。** この記事では、その実際の症状と、直し方を、そのまま書きます。
