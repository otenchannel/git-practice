# note で公開するときのメモ

出し先: **note**。本文は `02-managed-payments-tax-code.note.md`(表を箇条書きにした版)。
> 注意: note の編集画面の細かい仕様(表、コードブロック、見出しの段階、URL、メタディスクリプション)は、私は検索で確認できていません。**自分の編集画面で、先に試して確認する**こと。

## 確認できたこと(note 公式ヘルプ・検索結果から)
- note は、sitemap.xml を自動で発行し、Google に通知している([SEOに関するよくあるご質問(note ヘルプ)](https://www.help-note.com/hc/ja/articles/900006881223-SEO%E3%81%AB%E9%96%A2%E3%81%99%E3%82%8B%E3%82%88%E3%81%8F%E3%81%82%E3%82%8B%E3%81%94%E8%B3%AA%E5%95%8F))
- 見出しを設定すると、目次が自動で作られ、最初の見出しの上に表示される([note ヘルプ](https://www.help-note.com/hc/ja/articles/360012426133))
- note としては、SEO の個別の相談には答えにくい、という立場(同上、SEO のよくある質問)

## 確認できていないこと(先に、自分の編集画面で試す)
- [ ] **表**が使えるか(使えない前提で、箇条書きにしてある)
- [ ] **コードブロック**が使えるか。使えない場合は、インライン(`` ` ``)か、引用に変える。長いコードは、読みやすさのため、短くする
- [ ] **見出しの段階**が何段あるか(大見出し・小見出しの2段の可能性。H3 を使っている所は、段を合わせる)
- [ ] **記事の URL**を、自分で決められるか(決められない場合、タイトルとスラッグ案の効果は、タイトル側にしか期待できない)
- [ ] **メタディスクリプション**の入力欄があるか(なければ、記事の冒頭の数行が、検索結果の説明になりやすいので、冒頭を丁寧に書く)
- [ ] **ハッシュタグ**の数と使い方(非公式の情報では、note では、数個あれば十分、という話があるが、確認する)

## note 向けに変えた点
- 表を箇条書きにした(税コードの一覧)
- 先頭の公開メタ(タイトル案、スラッグ案など)と、末尾の告知文・公開前チェックを、本文から外した
- 構成(結論 → 症状 → 原因 → 直し方 → FAQ)は、そのまま。目次は、見出しから自動で作られる

## 見出し画像
- `docs/articles/images/02-eyecatch.png`(1280x670)を、note の「見出し画像」に設定する
- 新しい記事では、`python3 tools/articlebot/articlebot.py eyecatch <記事.md> --sub "説明"` で、HTML を作り、ブラウザでスクリーンショットを撮る
- 画像に、秘密の値や個人情報が入っていないか、確認する(タイトルと説明文だけなので、通常は問題なし)

## note の入力欄との対応
| 入力欄 | 入れるもの |
|---|---|
| タイトル | `Stripe「product tax code is missing」400の原因と対処【Managed Payments】`(長ければ、別案) |
| 見出し画像 | `docs/articles/images/02-eyecatch.png` |
| 本文 | `02-managed-payments-tax-code.note.md` の内容(先頭のコメント行は削除) |
| ハッシュタグ | #Stripe #Python #決済 #Webhook など、3〜5個 |
| 公開設定 | 最初は「無料」で公開 |

## note で、有料にするかどうか(今は、無料のままにする)
- 最初の記事は、**無料で公開**するのがおすすめです。見てくれる人を集めるための記事だからです。
- note には、有料記事の機能もあります。のちに、手順書を note で販売する選択肢も、ありえます。ただし、手数料や規約は、note のヘルプで確認してください(私は確認していません)。
- 自前の販売サイトを作ったので、**どこで売るか**(自前 / note / 両方)は、手順書が完成した頃に、決めれば大丈夫です。
