# デジタル商品販売 自動化プラン

「不労所得」は正確には「初期に作り込み、運用をほぼ自動化した収入」です。放置で稼げるわけではなく、
**商品作成(一度きり)→集客(継続)→販売・納品(自動)→サポート(最小化)** のうち、販売・納品を自動化するのがこの仕組みの範囲です。

## 1. 収益モデル
- 売るもの: 電子書籍 / テンプレート / スクリプト・ツール / 教材(原価ゼロで在庫なし)
- 価格例: 1,000〜5,000円の単品 → 慣れたら上位版・サブスクを追加
- 目安: 月5万円 = 1,980円 × 約26本/月。必要なのは「商品の質」と「集客」

## 2. 全体構成
```
集客(SNS/ブログ/SEO) → 販売ページ → 決済(Stripe/BOOTH/note等)
        → Webhook → 注文確定 → 署名付き期限付きDL URL をメール送信 → 顧客
```
`store/` に「Webhook以降」のプロトタイプがあります(下記参照)。

## 3. 自動化できる範囲と手作業の範囲
| 工程 | 自動化 | 備考 |
|---|---|---|
| 決済・納品 | ◎ | 本リポジトリのプロトタイプ / Stripe+メール配信 |
| 領収書・請求 | ○ | 決済サービス標準機能 |
| 集客 | △ | 予約投稿・SEO記事。品質は手作業が必要 |
| 問い合わせ | △ | FAQ整備+定型返信で削減 |
| 商品作成 | × | 最初の一番の工数 |

## 4. 進め方
1. **商品を決める**(自分の経験・スキルで悩みを解決するもの1つ)
2. 最初は自作せず **BOOTH / Gumroad / note / Stripe Payment Links** で販売開始し需要を検証
3. 売れ始めたら本プロトタイプを元に自前の納品自動化へ(手数料削減・独自体験)
4. 集客の型(週1記事+SNS予約投稿)を固定して運用コストを下げる

## 5. 本番化チェックリスト
- [x] 決済を Stripe に接続(Checkout + Webhook署名検証。テストモードで要動作確認)
- [x] メール送信を実装(SMTP。失敗時はStripe再送で再試行)
- [ ] `WEBHOOK_SECRET` / `DOWNLOAD_SECRET` を環境変数で本番値に
- [ ] HTTPS化、永続ストレージ、バックアップ
- [ ] 特定商取引法表記・プライバシーポリシー・利用規約(日本で販売する場合は必須)
- [ ] 売上の記録と確定申告(副収入が年20万円超で申告対象になるのが一般的。税理士/税務署に確認)
