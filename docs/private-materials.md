# 非公開資料の取り扱いと3Dデータ生成手順

**このリポジトリは公開設定。** 枚方市文化財課から頂いた資料(地形図・構造図・整備概要(案))の画像と、そこから起こしたデータはコミットしない。

## 除外しているもの(`.gitignore`)
- `data/raw/**` … 頂いた資料の写真(置き場: `data/raw/terrain/`)
- `data/private/` … 転記した表・標高点・抽出した領域・生成メッシュ
- `unity/KuzuhaDaiba/Assets/StreamingAssets/private/`

コミットしてよいのは、手順・コード・出典の台帳(提供元と日付のみ)・未確認事項。資料の転載や再配布の可否は市に確認する(Q14, Q17)。リポジトリを非公開にすれば、この制限は緩められる。

## 再生成手順
写真を `data/raw/terrain/` に置いてから実行する(Pillow と numpy が必要)。
```
python3 tools/extract_map_regions.py data/raw/terrain/20261014_hirakata_map_overlay.jpg data/private/geo --scale 0.353
python3 tools/build_provisional_mesh.py data/private/geo/regions.json data/private/geo/object-map.json data/private/geo/mesh --scale 0.353
```
標高の基準(Y=0)と地面のDEMを付ける場合の手順は `docs/elevation-datum.md`。
出力: `kuzuha_provisional.obj/.mtl`(暫定メッシュ)、`object-ledger.csv`(部材ごとの根拠区分)、`preview_topdown.png`、`mesh-stats.json`。
斜めからの確認用: `python3 tools/preview_oblique.py data/private/geo/mesh/kuzuha_provisional.obj out.png <東m> <北m> <半径m> --flip-x --az 200`

## Unityへの取り込み
1. Unityのプロジェクトに `Assets/Private/` フォルダを作る(**このフォルダは.gitignoreで除外済み**。名前を変えるとコミットされるので注意)。
2. `kuzuha_provisional.obj` と `kuzuha_provisional.mtl` を同じ場所にドラッグして入れる(読み込みに十数秒かかる)。
3. objを選び、Inspector の Model タブで Scale Factor=1、Mesh Compression=Off を確認して Apply。
4. Materials タブ → Extract Materials で `Assets/Private/Materials/` に取り出す。URPではそのままだとピンクになるので、Window > Rendering > Render Pipeline Converter で Built-in to URP の Material Upgrade を実行する(または各マテリアルのシェーダーを Universal Render Pipeline/Lit にして Base Map の色を元の色に合わせる)。
5. シーンに置き、**Scene ビューを上面(Top)にして向きを確認する**: 東が+X(右)、北が+Z(上)。番所が原点付近、火薬庫が右上(東へ約111m、北へ約20m)、南大堀が下側にあれば正しい。左右が逆なら鏡像なので `--no-flip-x` で作り直す。
6. 寸法の確認: 番所の長辺が約15.8m。Hierarchy には site_terrain と、部材ごとの子オブジェクトが並ぶ。

## 精度と限界(重要)
- 写真は未補正(台形歪み・折り目あり)。**縮尺は0.353 m/px(±3%)**。現存する地物(京阪線路・東西道路)の距離を地理院地図で測って決めた。詳細と限界は `docs/scale-calibration.md`。
- 領域は手彩色の範囲を機械的に抽出したもので、測量線ではない。位置の根拠区分はC止まり。
- 赤の線は凡例がなく意味不明のため、モデルには使っていない。
- 土塁・堀の断面は台形ではなく、領域に高さ・深さを与えて3×3平滑化を2回かけた仮の斜面。
- 堀(西面・北・東)の深さは根拠がなく、1mの仮値(根拠区分U)。
- 地面は平坦と仮定。標高点では台場内が約13.2m、東側が約15.5mで、実際は東が約2m高い。DEMを入手して置き換える。

## 出力する2種類のメッシュ
同じ形で、色だけが違う2つのOBJ(+MTL)を出す。
- `kuzuha_natural.obj`: 自然な色(草地・土・石・木・瓦・漆喰)。見た目の確認・VR体験用。
- `kuzuha_provisional.obj`: 根拠区分で色分け(橙=位置は推定、灰青=断面が未確認、赤紫=視覚補完)。分析・根拠の説明用。

土塁・堀の断面は、手彩色の領域を整備案の底幅まで外側へ広げ、法面(勾配1:1.5。南の堀の石垣はほぼ垂直)の付いた台形にしている(従来の平滑化は `--legacy-blur`)。堀と土塁が重なる所は堀を優先する。格子は既定1m。細かくするなら `--cell 0.5`(ファイルは約4倍)。

## 地面が消えて見える場合
- 地面は上からだけ見える片面なので、**カメラが地面より下に入ると消える**。Y=0 を川の水際(標高5.0m)にしたため、台場の地面は Y=+8〜+25m にあり、Scene ビューが原点(Y=0)付近を中心に回ると、低い角度ではカメラが地面の下に入る。
- 対処: (1) Hierarchy で対象を選び Scene ビュー上で F キー(対象に合わせて視点を移動)。(2) 上から見る。(3) マテリアルの Render Face を Both にする(両面表示)。
- メッシュ側では、地面の外周から下へ壁を立て、底面を張って箱状の土台にした(`--skirt-depth 3`、0で無効)。外側からはどの角度でも地面や断面が見える。カメラが箱の内側にある場合は、Render Face=Both が必要。

## 設計図と地形図の位置合わせ
構造図(設計図に整備番号が書き込まれたもの)は、地形図に対して約33°回転して描かれている。番所・見切塁・火薬庫・南東端の4点で相似変換を求めた(倍率0.77、残差0.3〜1.9m。`tools/similarity_fit.py`)。この変換で、設計図上の番号(⑧⑨⑬⑯⑱など)の位置を地形図の座標へ移す。対応点は `data/private/geo/panel-registration.json`。

- 目測で置いた虎口との照合: 南・東は7〜8mの差で近かった。**北虎口は1と2が入れ替わっていた**(設計図では、京街道接続側の北虎口1が西、作業道接続側の北虎口2が東の既存道路付近)。北は設計図の位置を採用し、南・東は両者の平均とした。
