# 商品企画: 「ゼロから作る、デジタル商品の販売自動化」手順書 + スターターキット

> 状態: **下書き**。売る前に「6. 販売前に確認すること」を必ず済ませる。
> 方針: 実際に起きたこと・動いたものだけを書く。収入の見込みや実績は書かない。

## 1. 誰の、どんな困りごとか
- **対象**: プログラミングに少し触れたことがあり、デジタル商品(電子書籍・テンプレートなど)を自分で売る仕組みを持ちたい人
- **困りごと**: BOOTH / note などの手数料や制約を超えて、自前で「決済 → メール → ダウンロード」を自動化したい。だが決済・Webhook・メール・公開の設定でつまずく
- **約束できること**: 動く実物(コード)と、つまずきやすい箇所の手順。**売れること・稼げることは約束しない**

## 2. 商品の中身
**A. 手順書(PDF または Markdown、30〜50ページ目安)**
**B. スターターキット(ZIP)**: 動く販売サイトの一式
- `store/` (販売ページ、Stripe Checkout、Webhook署名検証、SMTPメール、期限付きDLリンク)
- `tests/`(テスト15件)、`Dockerfile`、`render.yaml`、`fly.toml`
- `docs/`(デプロイ手順、本番化チェックリスト)

## 3. 手順書の目次案(実際に起きたことをもとに)
1. 全体像と、自動化できる範囲/できない範囲
2. 仕組み: 決済 → Webhook → 署名検証 → 期限付きURL → メール
3. ローカルで動かす(テストの実行)
4. Stripe を設定する(サンドボックス、APIキー、Webhook)
5. メール送信を設定する(SMTP、Gmail のアプリパスワード)
6. Render に公開する(Blueprint、環境変数、永続ディスク)
7. **つまずきやすい点と直し方(実録)**
   - APIキーを「表示」せずにコピーし、`sk_test_` だけが入ってしまう(401)
   - Webhook の署名シークレットが仮の値のまま(長さをログで確認する方法)
   - Stripe の Managed Payments が有効で、商品の税コードを求められる(400)
   - `SMTP_HOST` にメールアドレスを入れてしまう(`Name or service not known`)
   - ログが見えない(Live tail は、開いた後のログだけ。時間範囲を変える)
   - 失敗した Webhook を、Stripe の「再送信」でやり直す
8. 安全面: 秘密情報を環境変数に置く、モック決済を本番で無効にする、起動時の設定チェック
9. 本番化チェックリスト(特商法の表記、Stripe 本番、返金までの通し確認)
10. 運用とコスト、よくある質問

## 5. 販売ページの文章(下書き。`store/static/index.html` と `products.json` に反映する)

**見出し**
> 手数料に縛られず、自分の販売サイトを持つ。決済からメール納品まで、動く実物つき。

**リード文**
> デジタル商品を自分で売りたい。でも、決済、Webhook、メール、公開の設定でつまずく。
> この手順書とスターターキットは、実際に「決済 → メール → ダウンロード」まで動かした記録と、その一式のコードです。

**こんな人に**
- プログラミングに少し触れたことがあり、自前の販売サイトを持ちたい
- BOOTH や note ではなく、自分のドメインと流れで売りたい
- 設定でつまずいた時の、具体的な直し方が知りたい

**含まれるもの**
- 手順書(PDF): 設定から公開まで、つまずきやすい点の実録つき
- スターターキット(ZIP): 販売ページ、Stripe 決済、メール納品、テスト、デプロイ設定

**できること / できないこと**
- できる: 決済完了後の自動メール納品、期限付きダウンロードリンク、二重送信の防止
- できない: 集客(売れるようにすること)は含まれません。売上を保証するものではありません

**動作環境**
- Python 3.13、Stripe アカウント、メール送信用のアカウント、公開先(Render など。有料プランが必要になる場合があります)

**ご購入前にご確認ください**
- Stripe や Render などの外部サービスの画面や料金は、変わることがあります
- 税務・法務(特定商取引法の表記、消費税、インボイスなど)の助言は含みません
- デジタル商品の性質上、ダウンロード後の返品・返金はできません(商品に不備がある場合はご連絡ください)

## 6. 販売前に確認すること(必須)
- [ ] **まっさらな環境で、手順書どおりに最初から最後までやり直し、動くことを確認する**(誰かに試してもらうのが理想)
- [ ] キットに**秘密情報や個人情報が入っていない**ことを確認する(`.env`、APIキー、メールアドレス、注文データ `orders.db` など)
- [ ] キットの**利用条件を決める**(個人・商用の利用可否、再配布・転売の禁止、保証なし、サポートの範囲)
- [ ] 手順書のスクリーンショットに、**キー・パスワード・個人情報が写っていない**ことを確認する
- [ ] 外部サービス(Stripe、Render、Google)の**規約で禁止されていない使い方**であることを確認する
- [ ] 特商法の表記(環境変数 `LEGAL_*`)を設定する → `docs/go-live.md`
- [ ] **商品ファイルの置き場所**: 手順書とキットは `store/products/` に置く。リポジトリが公開(public)だと誰でも見られるため、**リポジトリを非公開にする**か、別の保管場所に移す
